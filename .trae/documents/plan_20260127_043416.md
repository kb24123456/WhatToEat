# 修复城市筛选状态不同步问题

## 问题分析

### 问题现象
1. 手动选择重庆后列表不显示餐厅
2. 添加餐厅后列表显示，但地区筛选失效
3. 再次选择重庆后列表不显示

### 根本原因

**城市状态与 UserDefaults 同步存在时序问题**：

1. `CitySelectionView` 中 `selectedCity = city` 通过 `@Binding` 更新 `LibraryView` 的 `selectedCity`
2. 触发 `.onChange(of: selectedCity)` 保存到 UserDefaults
3. 但 `@Query` 依赖 `selectedCity` 进行筛选，可能没有及时响应

**关键问题**：
- 通知触发时同步城市，但 `@Query` 刷新可能滞后
- 城市选择器显示的值与 `selectedCity` 实际值可能不一致
- `currentDistricts` 是计算属性，在 `selectedCity` 变化时不会触发 SwiftData 刷新

## 修复方案

### 方案1：添加强制刷新机制

在 `LibraryView` 的 `@Query` 中添加显式依赖，强制刷新：

```swift
@Query private var restaurants: [Restaurant]
```

改为使用带过滤的 Query，但这需要 Swift 5.9+。

### 方案2：在通知处理中强制视图刷新

```swift
.onReceive(NotificationCenter.default.publisher(for: .restaurantListShouldRefresh)) { _ in
    if let savedCity = UserDefaults.standard.string(forKey: "UserSelectedCity") {
        // 强制设置，即使值相同也确保状态同步
        selectedCity = savedCity
    }
    print("RestaurantListRefresh: 收到刷新通知")
}
```

### 方案3：添加调试日志定位问题

在关键位置添加日志，确认数据流是否正确。

## 推荐方案

实施 **方案2**：移除值比较检查，确保每次通知都强制同步城市状态。
