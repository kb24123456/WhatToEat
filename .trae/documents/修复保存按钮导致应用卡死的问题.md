### 问题根本原因
当前的 `saveRestaurant()` 方法是同步的，它在主线程上执行了两个耗时操作：
1. `image.jpegData(compressionQuality: 0.6)` - 图片压缩（尤其是大图片）
2. `try imageData.write(to: fileURL)` - 文件写入（阻塞IO操作）

这些操作会阻塞主线程，导致应用程序无响应。

### 修复方案
1. **将saveRestaurant()改为异步方法**：使用`async/await`确保UI线程不被阻塞
2. **添加加载状态**：显示"保存中..."指示器，提升用户体验
3. **后台执行图片操作**：将图片压缩和保存移到后台线程
4. **显式保存数据**：添加`try modelContext.save()`确保数据持久化
5. **完善错误处理**：捕获并处理可能的异常
6. **优化状态管理**：确保状态更新和视图关闭的正确顺序

### 修改步骤
1. **添加加载状态变量**：
   ```swift
   @State private var isSaving = false
   ```

2. **修改saveRestaurant()方法为异步**：

   private func saveRestaurant() {

       // 后台保存图片
       let filename = await saveImageInBackground(selectedImage)

3. **实现后台图片保存**：
   ```swift
   private func saveImageInBackground(_ image: UIImage?) async -> String? {
       return await Task.detached {
           image.flatMap { ImageManager.shared.saveImage($0) }
       }.value
   }
   ```

4. **更新UI**：

   - 添加全屏半透明加载覆盖

### 预期效果
- 点击保存按钮后，立即显示"保存中..."指示器
- 应用程序保持响应，不会卡死
- 图片处理在后台执行
- 数据成功保存到SwiftData

### 技术要点
- 使用`async/await`进行异步编程
- 利用`Task.detached`在后台线程执行耗时操作
- 使用`MainActor.run`确保UI更新在主线程执行
- 显式调用`modelContext.save()`确保数据持久化
- 添加适当的错误处理机制
