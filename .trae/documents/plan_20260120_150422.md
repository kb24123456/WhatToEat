### 1. 根本原因分析

#### 可能的根本原因
- **SwiftData操作阻塞主线程**：`modelContext.insert(newRestaurant)`可能是一个耗时操作，阻塞了主线程
- **视图销毁后状态更新**：`dismiss()`调用后，视图被销毁，但代码仍尝试更新`isSaving`状态
- **异步操作顺序问题**：异步操作的执行顺序可能导致UI更新冲突
- **内存或资源泄漏**：长时间运行的操作导致内存占用过高

#### 详细排查步骤

1. **检查应用日志**
   - 运行应用并尝试保存，查看Xcode控制台输出
   - 检查是否有SwiftData相关的错误或警告
   - 查看是否有文件系统操作的错误

2. **检查内存使用情况**
   - 在Xcode中使用Instruments工具，监控内存使用和CPU占用
   - 特别关注保存按钮点击前后的内存变化

3. **检查保存功能相关代码逻辑**
   - 分析`saveRestaurant()`方法的执行流程
   - 检查`modelContext.insert()`是否在主线程执行
   - 检查`dismiss()`调用后是否还有状态更新

4. **检查资源占用情况**
   - 监控文件系统操作的耗时
   - 检查图片处理是否占用过多资源

### 2. 解决方案

#### 优化saveRestaurant方法

1. **调整状态更新顺序**：在调用`dismiss()`之前设置`isSaving = false`
2. **确保SwiftData操作高效**：检查SwiftData模型定义和关系
3. **移除不必要的状态更新**：避免在视图销毁后更新状态
4. **添加超时处理**：为耗时操作添加超时机制

#### 具体修改方案

1. 修改`saveRestaurant()`方法，调整状态更新顺序
2. 确保所有UI更新都在正确的时间点执行
3. 优化SwiftData操作，避免阻塞主线程
4. 添加错误处理和日志记录，便于调试

```swift
private func saveRestaurant() async {
    // 显示加载状态
    await MainActor.run { isSaving = true }
    
    // 1. 处理标签字符串转数组
    let tags = tagsInput.split(separator: ",")
        .map { $0.trimmingCharacters(in: .whitespacesAndNewlines) }
        .filter { !$0.isEmpty }
    
    // 2. 将图片保存到磁盘并获取文件名
    let filename = await saveImageInBackground(selectedImage)
    
    // 3. 创建餐厅对象
    let newRestaurant = Restaurant(
        name: name,
        type: cuisine,
        district: district,
        rating: rating,
        address: address,
        latitude: latitude,
        longitude: longitude,
        coverPhotoFilename: filename,
        review: review,
        tags: tags,
        averagePrice: 0.0
    )
    
    // 4. 更新UI状态
    await MainActor.run {
        // 在插入前更新状态，避免dismiss后更新
        isSaving = false
        
        // 存入 SwiftData
        modelContext.insert(newRestaurant)
        
        // 关闭视图
        dismiss()
    }
}
```
