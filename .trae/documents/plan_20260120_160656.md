### 应用程序白屏问题诊断与修复方案

#### 可能的根本原因
1. **自定义对齐指南导致渲染崩溃**：`RestaurantCard` 中的 `.alignmentGuide(.top) { _ in -8 }` 可能导致SwiftUI渲染引擎崩溃
2. **直接在视图构建中加载图片**：`ImageManager.shared.loadImage(filename: filename)` 在视图构建过程中同步加载图片，可能导致性能问题
3. **SwiftUI渲染循环**：`FilterPositionKey` 偏好键的使用可能导致渲染循环
4. **UIScreen.main.bounds.width 使用**：在视图构建中直接访问屏幕尺寸可能导致问题
5. **LocationManager 初始化问题**：可能存在权限问题或其他运行时错误

#### 修复方案

1. **移除问题对齐指南**：
   - 删除 `RestaurantCard` 中第396行的 `.alignmentGuide(.top) { _ in -8 }`
   - 使用更可靠的对齐方式，如 `padding` 或 `Spacer`

2. **优化图片加载**：
   - 考虑使用异步图片加载
   - 或使用 SwiftUI 的 `AsyncImage`
   - 至少确保图片加载不会阻塞主线程

3. **修复渲染循环问题**：
   - 检查并优化 `FilterPositionKey` 的使用
   - 确保偏好键不会导致无限渲染循环

4. **替换 UIScreen.main.bounds.width**：
   - 使用 GeometryReader 或其他更安全的方式获取屏幕尺寸

5. **优化 LocationManager 使用**：
   - 确保 LocationManager 初始化不会阻塞主线程
   - 添加合适的错误处理

#### 修改步骤

1. **修改 RestaurantCard 组件**：
   - 删除第396行的 `.alignmentGuide(.top) { _ in -8 }`
   - 优化图片加载逻辑

2. **修改 LibraryView 组件**：
   - 替换 `UIScreen.main.bounds.width` 为 GeometryReader
   - 优化 FilterPositionKey 的使用

3. **添加错误处理**：
   - 在 LocationManager 中添加合适的错误处理
   - 确保权限请求不会导致应用崩溃

#### 预期效果
1. 应用程序能够成功启动，不再出现白屏
2. 界面渲染流畅，没有明显卡顿
3. 所有功能正常工作
4. 应用程序稳定，不会崩溃

#### 技术要点
- 移除导致SwiftUI渲染崩溃的自定义对齐指南
- 优化图片加载，避免阻塞主线程
- 修复可能的渲染循环问题
- 安全使用屏幕尺寸
- 添加合适的错误处理
