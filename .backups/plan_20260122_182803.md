# 将城市名省略"市"字的实现计划

## 实现思路
1. 修改regions.json文件，将所有城市名中的"市"字去除
2. 确保RegionManager能正确处理修改后的城市名
3. 检查相关代码，确保城市选择和筛选功能正常工作
4. 考虑数据兼容性，确保现有餐厅数据能正确匹配

## 实现步骤

1. **修改regions.json文件**
   - 将所有城市名中的"市"字去除，例如：
     - "北京市" → "北京"
     - "上海市" → "上海"
     - "广州市" → "广州"
     - 特殊情况："重庆市" → "重庆"
   - 保留其他城市名不变，如"深圳市" → "深圳"

2. **检查RegionManager**
   - 确保RegionManager能正确加载和处理修改后的城市名
   - 验证`allCities`属性和`getDistricts(for:)`方法能正常工作

3. **检查LibraryView**
   - 确保城市选择器能正常显示和切换修改后的城市名
   - 验证地区筛选功能能正确获取修改后城市的区列表
   - 确保筛选逻辑能正确匹配餐厅数据

4. **处理数据兼容性**
   - 考虑现有餐厅数据中city字段可能包含"市"字的情况
   - 确保筛选逻辑能正确处理这种情况，或者考虑数据迁移

## 代码实现要点

1. **修改regions.json**
   - 直接编辑JSON文件，将所有城市名中的"市"字去除
   - 确保JSON格式正确，没有语法错误

2. **修改筛选逻辑（可选）**
   - 如果现有餐厅数据中的city字段包含"市"字，需要在筛选时进行兼容处理
   - 例如，在ViewModel的`processRestaurants`方法中，将餐厅的city字段和selectedCity都转换为统一格式后再比较

## 预期效果

- 城市选择器中显示的城市名从"北京市"变为"北京"
- 地区筛选功能能正确获取修改后城市的区列表
- 餐厅筛选功能正常工作，不受城市名格式变化影响
- 整体UI显示更简洁，符合用户期望

## 潜在风险及解决方案

1. **数据不匹配风险**
   - 风险：现有餐厅数据中的city字段包含"市"字，导致筛选不匹配
   - 解决方案：在筛选时进行字符串处理，去除餐厅city字段中的"市"字后再比较

2. **代码引用风险**
   - 风险：代码中可能直接引用了包含"市"字的城市名
   - 解决方案：全面检查代码，确保所有城市名引用都使用动态获取的方式

3. **用户体验风险**
   - 风险：用户可能习惯了包含"市"字的城市名
   - 解决方案：用户调研或A/B测试，确保修改后的显示效果更受欢迎

这个计划确保了城市名修改的顺利进行，并考虑了各种潜在风险和解决方案，能有效保证系统的稳定性和用户体验。
