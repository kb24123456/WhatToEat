# 头像裁剪、深色统一与展开态切换实现计划

## 目标
- 在头像编辑页补齐“相册确认 -> 圆形裁剪 -> 保存头像”的完整链路。
- 统一深色模式下头像名片、功能设置展开卡片与收缩态入口卡片的颜色语义。
- 让功能设置展开动画与数据卡片展开动画一致，并支持两种展开态之间的直接切换。
- 在沉浸式决策页复用底部导航条隐藏动效。
- 调整消费信息中的“人数”数值对齐，并评估是否需要更高级交互。

## 范围
- `WhatToEat/ProfileView.swift`
- `WhatToEat/ImmersiveDecisionView.swift`
- `WhatToEat/CheckInView.swift`

## 实施步骤
1. 分析 `EditProfileView` 现有 `PhotosPicker` 链路，替换为支持系统确认按钮的相册选择器，并在选择后进入自定义圆形裁剪页。
2. 为头像裁剪页实现原生风格的拖拽/缩放、圆形遮罩和确认导出，输出可直接写回 `avatarData` 的图片数据。
3. 抽取 Profile 页深色模式下统一的卡片表面、描边和按钮表面 token，应用到头像名片、收缩态入口卡片和功能设置展开卡片。
4. 把功能设置展开区的 transition 调整为与数据卡片一致，并在展开态顶部加入“切换到另一面板”的按钮。
5. 在 `ImmersiveDecisionView` 的生命周期里发送 `hideTabBar` / `restoreTabBar` 通知，复用现有底部导航动效。
6. 调整 `CheckInView` 的人数数字字号与基线；对滚轮/滚动控制进行场景评估，仅在确认收益明显时再改交互。
7. 运行构建验证；若仍受当前 Xcode/Simulator 环境限制，明确记录阻塞点。

## 风险与对策
- 头像裁剪若直接依赖 `PhotosPicker` 无法得到系统右上角确认行为，因此改用 `PHPickerViewController` 包装器。
- 圆形裁剪容易出现导出坐标偏差，需要基于实际显示 frame 和缩放偏移反算裁剪矩形，并限制最小缩放。
- 展开态切换若在已有大卡片 overlay 打开时触发，会引发状态冲突；切换前先关闭当前展开卡片。
- 当前仓库工作区较脏，编辑时只触达本轮相关文件，避免覆盖用户未提交修改。

## 验证
- 手动检查头像编辑链路：打开相册、确认、裁剪、保存。
- 检查深色模式下收缩/展开态颜色一致性。
- 检查数据卡片/功能设置切换时动画和底部导航隐藏是否连续。
- 检查人数数字高度是否与消费/人均一致。
